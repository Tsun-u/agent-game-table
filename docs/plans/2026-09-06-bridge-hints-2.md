**目標：** `suggestCall` 多三種處境：搭檔開弱二的第一次應叫、搭檔開一線花色後右手對手技術性 Double 時的第一次應叫、搭檔技術性 Double 後（右手對手 PASS）的第一次應叫。

**方法：** 只改 `src/engine/bridge-systems.ts` 與 `test/bridge-systems.test.ts`，在 `suggestCall` 的處境分派加三條，各對應一個新函式。三套制度在這三段沒有差異。

### 任務 1：三個新處境（小葵）

**檔案：** 修改 `src/engine/bridge-systems.ts`

- [x] 步驟 1：**對搭檔弱二的應叫**（搭檔第一聲是 `2♦`／`2♥`／`2♠`，自己還沒叫、右手對手 PASS；花色 W）：
  1. W ≥ 3 張且 HCP ≥ 14 → `4W`（高花）／`5W`（♦）「N 點、三張支持，直接叫成局」
  2. W ≥ 3 張且 HCP < 14 → `3W`「阻擊性加叫」
  3. HCP ≥ 15 → `2NT`「問特徵，有成局興趣」
  4. HCP ≥ 14 且有 5+ 張非 W 的花色 → 該花色最低線（RONF，逼叫一輪）
  5. 否則 `PASS`「不夠成局，弱二就讓它打」
- [x] 步驟 2：**搭檔開一線花色 S、右手對手 Double 後的應叫**（auction 是 S、X，自己第一次開口）：
  1. S ≥ 3 張且 HCP ≥ 10 → `2NT`「限制性加叫或更好」
  2. S ≥ 4 張且 HCP < 10 → `3S`「阻擊性加叫」
  3. S ≥ 3 張且 HCP 6–9 → `2S`
  4. HCP ≥ 6 且有 4+ 張能在一線叫的高花（比 S 高）→ `1M`（往上叫；S 是 ♥ 時只有 ♠）
  5. HCP ≥ 10 → `XX`「10 點以上、沒有配合，Redouble」
  6. HCP 6–9 → `1NT`
  7. 否則 `PASS`
- [x] 步驟 3：**搭檔技術性 Double 後的應叫**（對手開一線花色 O，搭檔 `X`，右手對手 PASS，自己第一次開口；未叫花色＝O 以外三門）：
  1. HCP ≥ 12 → `2O`「叫對手花色，逼叫成局」
  2. 平均牌型且 O ≥ 2 張：HCP 11–12 → `2NT`；6–10 → `1NT`
  3. HCP 9–11 → 未叫花色中最長的（等長高花優先、等長高花再取 ♠）跳一線
  4. 否則 → 未叫花色中最長的最低線「N 點，搭檔 Double 不能 PASS」（0 點也要叫）
- [x] 步驟 4：`suggestCall` 的分派：
  - 弱二：`first.seatId === partner`、`first.call` 是 `2♦`／`2♥`／`2♠`、`mine.length === 0`、右手對手那聲是 PASS
  - 對手 Double：`first.seatId === partner`、一線花色、auction 恰好是 [S, X]（右手對手 X）、自己第一次開口。**現有「auction 有 X 就回 null」那條要改成只擋沒對應處境的情況**
  - 搭檔 Double：對手開一線花色、搭檔那聲是 `X`、右手對手 PASS、自己第一次開口
  - 步驟 11 的合法性過濾照舊（`XX` 要在自己方被 Double 時才合法，加一條）
