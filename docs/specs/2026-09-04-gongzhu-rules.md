# 拱豬（含傷心小棧模式） 規則文件

> 狀態：童童 2026-09-04 核可（五個確認項的答覆已併入內文）。實作計畫：`docs/plans/2026-09-04-gongzhu.md`。
> 依據：童童 2026-09-04 口述的玩法為預設；變體整理自維基百科台灣版與幾篇玩法整理，全部做成預設關閉的桌面開關。**不做亮牌**（童童決定）。

## 一、基本玩法（預設，童童版）

- **人數**：固定四人（`seats: { min: 4, max: 4, fixed: true }`）。不足四人不能開局。
- **牌**：52 張全發，每人 13 張。
- **首出**：持 ♣2 者先出，第一墩必須出 ♣2。
- **跟牌**：跟首出花色；沒有該花色才能墊任何牌。每墩由首出花色中最大的牌贏，贏家收墩並首出下一墩。
- **牌的大小**：A 最大、2 最小（同花色內 A > K > … > 3 > 2）。
- **一局結束**：13 墩打完，各家依收到的分數牌算分。
- **累積與結束**：分數累加。結束條件是桌面選項（見下）：分數制預設任一家累積到 -1000（含）以下整場結束；局數制預設打滿 4 局結算。整場結束時分數最高者勝。

### 分數牌

| 牌 | 分 |
|---|---|
| ♥A | -50 |
| ♥K | -40 |
| ♥Q | -30 |
| ♥J | -20 |
| ♥10 到 ♥5 | -10 |
| ♥4、♥3、♥2 | 0（但算「紅心」，全紅要收齊） |
| ♠Q（豬） | -100 |
| ♦J（羊） | +100 |
| ♣10（變壓器） | 見下 |

### 變壓器 ♣10

- 只收到 ♣10、沒有其他任何分數牌：+50。
- 收到 ♣10 加其他分數牌：其他分數牌合計 × 2（正負都乘）；♣10 本身不計分，也沒有「連自己一起乘」的版本。

### 全紅

收齊 13 張紅心：紅心全部變正分，合計 +200（原本 -200 的絕對值翻正）。豬、羊、變壓器照常計算，再乘變壓器。

計算順序：先算紅心（含全紅翻正）＋豬＋羊，再套變壓器。

## 二、可開關的變體（預設全關）

| key | 名稱 | 開啟時 |
|---|---|---|
| `end_mode` | 結束方式 | `score`（預設）：任一家累積分低於或等於 `end_score` 就結束；`rounds`：打滿 `end_rounds` 局結束 |
| `end_score` | 結束分數 | 數字，預設 -1000（傷心小棧預設 -100） |
| `end_rounds` | 結束局數 | 數字，預設 4 |
| `grand_slam` | 大滿貫 | 一家收齊所有分數牌（13 紅心＋♠Q＋♦J＋♣10）：全部變正分，總計 +800 |
| `hearts_low_zero` | 小紅心不計分 | 已是預設（♥2 到 ♥4 為 0 分）；關閉時 ♥2 到 ♥4 各 -10 |
| `transformer_alone_bonus` | 變壓器獨得加分 | 預設 +50；關閉時單獨收到 ♣10 算 0 分 |
| `heart_break_lead` | 紅心破牌後才能首出紅心 | 預設關（童童確認拱豬沒在守）。開啟時：還沒有人在墩裡出過紅心之前，不能用紅心首出（手上只剩紅心除外） |
| `partnership` | 對家配合 | 對家兩人分數合計，勝負以隊為單位（引擎內合併 scoreDelta，牌桌層仍記每人） |

下面這些變體查得到但**第一版不做**，列出來只是說明有意排除：暗賣、逼亮、分牌全亮、除羊全亮（都是亮牌系統的一部分）、豬羊變色（地區規則，來源說法不一）、三人／五人拱豬（人數不同會改牌張，另案）。

## 三、傷心小棧模式（`variant: "hearts"`）

同一個引擎、同一套跟牌與收墩，只換三件事：

- **分數牌**：紅心每張 -1（13 張共 -13）、♠Q -13；沒有羊、沒有變壓器。
- **開局傳牌**：發牌後每人選 3 張傳給指定方向（左、右、對家、不傳，四局輪替）。這是**四人同時行動**的階段：`pendingSeatIds` 回四席，全部傳完才進入出牌。
- **射月（Shoot the Moon）**：一人收齊全部 13 紅心＋♠Q：自己 0 分、其他三家各 -26。
- **首出**：持 ♣2 者先出，第一墩必含 ♣2；第一墩不能出分數牌（手上全是分數牌除外）。
- **紅心破牌後才能首出紅心**：預設開（跟拱豬相反）。
- **結束**：同樣走 `end_mode`／`end_score`／`end_rounds`，分數制預設 -100。

傷心小棧不提供拱豬的其他變體開關（`heart_break_lead` 固定開）。

## 四、引擎對應

### 共用核心 `trick-taking-core.ts`

拱豬、傷心小棧、之後的三種橋牌共用：

- `legalFollows(hand, leadSuit, extraRule?)`：跟花色規則，沒有該花色可墊任何牌。
- `trickWinner(trick, leadSuit, trump?)`：同花色比大小；橋牌會帶王牌。
- 狀態：本墩已出的牌（順序）、首出者、各家收到的牌堆。

### 拱豬引擎狀態

```ts
interface GongzhuState {
  phase: "passing" | "trick" | "ended";        // passing 只有傷心小棧模式會出現
  variant: "gongzhu" | "hearts";
  order: string[];                               // 四席，固定
  hands: Record<string, string[]>;
  captured: Record<string, string[]>;            // 各家收到的牌
  trick: { leader: string; plays: Array<{ seatId: string; card: string }> };
  heartsBroken: boolean;
  passDirection: "left" | "right" | "across" | "none";   // hearts 專用
  pendingPasses: Record<string, string[]>;               // hearts 專用：已選但未結算的傳牌
  active: string | null;
}
```

### legal_plays 與 legal_actions

- 出牌階段：`legal_plays` 是「這一手可以出的單張」清單（每張一組，`action: "play_card"`），伺服器已套用跟花色、破牌、首墩限制。AI 只從清單挑。
- 傳牌階段（hearts）：`legal_actions` 有 `pass_cards`，`legal_plays` 列出手牌（AI 自選三張，伺服器驗證是 3 張且都在手上）。
- `board`：本墩的牌與首出者、各家已收的分數牌（只露分數牌，不露非分數牌數量以外的資訊）、紅心是否已破、目前累積分。

### 結算

`RoundResult.scoreDelta` 每席位一筆。整場是否結束由牌桌層在寫完累積分後呼叫引擎的 `isGameOver(options, { round, scores })` 判斷（累積分在牌桌層、跟人走，引擎不持有）。`text` 用 `{name}` 樣板：「{name} 收豬又收變壓器，本局 -260。」這類公告由引擎組。

### 離桌

四人固定，局中離桌一律 `"abort"`（流局），與代打搭配。

## 五、前端

- 桌面：四個方位，中央顯示本墩四張牌（依出牌順序）、首出者標記；每家名字旁顯示本局已收的分數牌小圖示與累積分。
- 手牌：單張點選即出（不是大老二的多選），不合法的牌灰掉。
- 傷心小棧傳牌：手牌區出現「選 3 張傳給 左家／右家／對家」，四人都傳完才發下一步。
- 開桌表單：由 `/api/games` 產生，選「拱豬」或「傷心小棧」（同引擎兩個 mode 登錄，或一個 mode 加 variant 選項；建議前者，大廳與規則版本才分得開）。

## 六、童童的答覆（2026-09-04）

1. ♥2 到 ♥4 算 0 分但全紅要收齊：對。
2. 變壓器沒有連自己乘的版本。
3. 結束條件做成選項：分數制／局數制，數字可自填；分數制預設 -1000、局數制預設 4 局。
4. 傷心小棧與拱豬一起做進第一版。
5. 紅心破牌規則預設關、可開。
